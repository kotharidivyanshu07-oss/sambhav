**Build steps taken by Claude after Prompt 3** (no further user prompts —
the rest of the build was Claude working autonomously toward the stated
requirements, checked back against the original problem statement):

1. Scaffolded `lib/models.py` to match the exact request/response JSON
   shapes from the spec.
2. Wrote `lib/persona.py`: hand-tuned voice/stance/keyword profiles for the
   example personas in the brief (AI Security, ML Engineer, AI Product
   Analyst, Open Source Contributor, Robotics Engineer, Developer Advocate,
   AI Ethics Researcher), plus a deterministic fallback generator for any
   other domain string so no persona ever falls back to something generic.
3. Wrote `lib/discovery.py`: live topic discovery from the Hacker News
   Algolia search API and the arXiv Atom API, keyed off the persona's own
   keywords/domain, with graceful degradation if either source is
   unreachable.
4. Wrote `lib/editorial.py`: a transparent scoring function (keyword
   relevance, recency, novelty vs. memory via title-token Jaccard
   similarity, basic clickbait/quality heuristics) that decides accept vs.
   reject and logs the reason for both.
5. Wrote `lib/generator.py`: template-based post + rationale writer that
   assembles text from the persona's fixed stance list, deterministically
   varied per post via a seeded RNG.
6. Wrote `lib/storage.py`: Upstash/Vercel KV REST persistence with an
   in-memory fallback for local dev.
7. Wrote `lib/agent.py`: the orchestration layer — `create_agent`,
   `maybe_publish` (the self-scheduling catch-up loop that makes publishing
   autonomous under serverless constraints), and `public_posts`.
8. Wrote `api/index.py`: the FastAPI app exposing `POST /api/agent/init`,
   `GET /api/agent/feed`, plus an optional `GET /api/agent/tick` for a real
   external scheduler, and `GET /api/health`.
9. Added `vercel.json`, `requirements.txt`, and `README.md`.
10. **Self-review pass**: ran the app locally with `TestClient`, then with
    mocked discovery data to exercise the full discover → judge → publish
    cycle end to end. This surfaced a real bug — the catch-up loop
    rescheduled `nextPublishAt` from "now" instead of from the missed slot,
    so a long gap between polls collapsed into a single post instead of the
    several actually due. Fixed in `lib/agent.py::_schedule_next` and
    re-verified with a test forcing several intervals to be overdue at
    once (confirmed: 3 distinct posts published in one call, capped
    correctly, no duplicate topics, no extra posts on an immediate re-poll).
11. Wrote this file and the final repo layout.

No LLM API was called at runtime by the deployed agent itself — all post
text is generated by the deterministic template engine in
`lib/generator.py`, per the answer to Prompt 3's second question.

**Post-build debugging round (user running locally on Windows, via chat):**

After the initial build, the user ran the app locally to sanity-check it
before deployment. This surfaced two real, substantive bugs that were fixed
through iterative testing against live data rather than being caught by
static review:

1. **Discovery query was too narrow.** The original `_fetch_hn` combined
   4 persona keywords into a single Algolia search query. On a niche domain
   like "AI Security", this consistently surfaced the *oldest* best-matching
   story (some over 300 days old) rather than genuinely recent ones, because
   few recent stories matched all the combined terms. Fixed by running
   several separate single-keyword queries and merging/deduping results —
   verified against the live API (the user's machine, not Claude's sandbox,
   which has a restricted allowlist) that this returns a healthy mix of
   posts from the last few hours to ~2 weeks old.
2. **Editorial judgment allowed stale topics through on keyword density
   alone**, which produced a post whose rationale claimed a topic was
   "relevant now" while it was actually 171 days old. Fixed by adding a
   hard staleness cutoff (`MAX_TOPIC_AGE_HOURS`, initially 14 days, tuned
   to 30 days after live data showed 14 was unrealistically strict for a
   niche security-news volume) that rejects a candidate regardless of score
   if it's older than the cutoff — verified with a reproduction of the
   exact failing scenario before and after the fix.

Also encountered and fixed along the way: a Python 3.14 build-from-source
failure for `pydantic-core` (no prebuilt wheel yet for that exact pin — 
relaxed `requirements.txt` to version *minimums* instead of exact pins),
and a Windows-specific issue where an editor saved a `.py` file as RTF
instead of plain text (worked around by writing files via PowerShell
here-strings instead of Notepad/WordPad). An optional `/api/agent/debug`
endpoint (not part of the required spec) was added specifically to make
this kind of live diagnosis possible without guessing.
