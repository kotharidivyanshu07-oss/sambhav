# Ada — Autonomous AI Security Persona Agent

ABTalks hackathon submission: "Redesign ABTalks" — an autonomous AI/tech
persona that discovers topics, exercises editorial judgment, writes in a
consistent voice, remembers what it has published, and keeps publishing over
time with zero human input after initialization.

Default persona: **Ada, AI Security** — but `POST /api/agent/init` accepts
any `{name, domain}` and the agent builds a full voice profile for it (see
`lib/persona.py`).

## How it satisfies each requirement

| Requirement | Where |
|---|---|
| Topic discovery from a live source | `lib/discovery.py` — Hacker News (Algolia search API) + arXiv, queried with the persona's own keywords |
| Editorial judgment (rejects things) | `lib/editorial.py` — scores every candidate on keyword relevance, recency, novelty vs. memory, and basic quality heuristics; only publishes if it clears a threshold. Rejections are logged with reasons. |
| Consistent persona | `lib/persona.py` — fixed stances, tone, vocabulary, and signoff per persona, reused deterministically across every post |
| Memory | Published posts (with topic titles) are persisted per agent and checked against every new candidate for topical overlap before republishing |
| Autonomous publishing over time | See "How autonomy works under serverless" below |
| Rationale in every post | Each post's `rationale` states why the topic was picked, why it's relevant now, and what it beat out; `sources` lists the originating URL(s) |

## How autonomy works under serverless

Vercel's Hobby-tier Cron Jobs only run once a day, which is too coarse to
trickle posts out over 48 hours. So the agent doesn't rely on cron alone:

- Every stored agent has its own `nextPublishAt` timestamp, chosen by the
  agent itself (randomized 45–150 min after the previous post).
- On **every** `GET /api/agent/feed` call, the agent first checks its own
  clock: if `nextPublishAt` has passed, it runs discover → judge → write →
  publish (catching up on up to 3 missed cycles if the gap was long), then
  reschedules itself, *before* returning the feed.
- The caller supplies no topic, prompt, or content — only an `agentId`. The
  decision of *whether*, *what*, and *when* to publish is entirely the
  agent's own stored state and scoring logic.
- `GET /api/agent/tick` is also exposed as an optional push-style trigger,
  so a real external scheduler (Vercel Pro Cron, `cron-job.org`, a GitHub
  Actions schedule) can drive the same loop independently of anyone polling
  the feed at all. Called with no `agentId`, it ticks every agent that has
  been initialized.

## API

```
POST /api/agent/init
  { "persona": { "name": "Ada", "domain": "AI Security" } }
  -> { "agentId": "..." }

GET /api/agent/feed?agentId=...
  -> { "posts": [ { id, createdAt, text, rationale, sources } ] }
```

Both match the challenge spec exactly (see `lib/models.py`).

## Persistence

Serverless functions are stateless between invocations, so agent
state/memory is stored in **Upstash Redis via its REST API** (this is
exactly what "Vercel KV" provisions). To deploy:

1. Create a free Upstash Redis database (or attach a Vercel KV store to
   this project — same thing under the hood).
2. Set env vars on the Vercel project:
   - `KV_REST_API_URL`
   - `KV_REST_API_TOKEN`
3. Deploy. Without these two env vars set, the app still runs but falls
   back to an in-memory store that does **not** survive across separate
   invocations — fine for local testing, not for the 48h evaluation window.

## Local development

```bash
pip install -r requirements.txt fastapi[standard]
uvicorn api.index:app --reload
```

Then:
```bash
curl -X POST localhost:8000/api/agent/init \
  -H "Content-Type: application/json" \
  -d '{"persona": {"name": "Ada", "domain": "AI Security"}}'

curl "localhost:8000/api/agent/feed?agentId=<id from above>"
```
The first post appears ~5 minutes after init (by design — no instant dump),
then subsequent posts trickle in every 45–150 minutes, each time the feed is
polled after its scheduled slot.

## Deploy to Vercel

```bash
vercel --prod
```
`vercel.json` is already configured to route all four endpoints to
`api/index.py` and to attempt an hourly cron tick (upgrade to Vercel Pro for
crons more frequent than daily; the feed-poll-driven publishing above works
on any plan).

## Design notes / limitations

- Post text is generated by a **deterministic template engine** tied to each
  persona's fixed stance list and tone — no external LLM call is made at
  runtime (see `PROMPTS.md` for why, and where an LLM call could be dropped
  in at `lib/generator.py` if desired).
- Discovery sources are intentionally free/no-auth (HN Algolia, arXiv) so
  the deployed instance needs zero API keys beyond the KV store.
- Editorial scoring is a transparent, inspectable heuristic (see
  `lib/editorial.py`) rather than a black box — every accept/reject reason
  is logged and feeds directly into the published rationale.
